# What changed in Talos v1.14

Released 2026-09-03. Upstream notes:
https://docs.siderolabs.com/talos/v1.14/getting-started/what's-new-in-talos

This file is the canonical home for v1.14 behaviour changes. Other reference files link here rather
than restating them.

## Breaking

### The installer image is no longer published

`ghcr.io/siderolabs/installer:v1.14.0` returns **404**. `ghcr.io/siderolabs/installer:v1.13.10`
still resolves, so 1.13 and earlier are unaffected. `ghcr.io/siderolabs/imager` and
`ghcr.io/siderolabs/installer-base` are also unaffected and still published.

Installer images now come from the Image Factory. See `references/images/boot-assets.md` for the
path shape, the default schematic id, and how to find the schematic a node was installed from.

### etcd metrics and health moved from port 2379 to 2383

Same client mTLS, dedicated listener. Prometheus scrape configs and firewall rules pointing at 2379
break **silently** — the target simply stops returning data. Unaffected when `--listen-metrics-urls`
was set explicitly.

### etcd 3.6 is the minimum

v1.14 ships etcd 3.7.1 and is incompatible with etcd older than 3.6.

### multipath-tools requires a migration applied *before* upgrading

The extension now reads `/etc/multipath.conf` bind-mounted from the host and ships no default, so
`multipathd` waits forever for a file that never appears. Apply this first:

```yaml
apiVersion: v1alpha1
kind: ExtensionServiceConfig
name: multipathd
$patch: delete
---
apiVersion: v1alpha1
kind: EtcFileConfig
name: multipath.conf
mode: 0o644
contents: |
  defaults {
      user_friendly_names yes
      find_multipaths no
      path_selector "round-robin 0"
  }
```

### Other removals

- `talosctl apply-config --mode=reboot` is gone from the CLI. The wire enum `REBOOT` still exists and is accepted, marked deprecated — so `talos_apply_config(mode="reboot")` keeps working. Prefer `auto` or `no-reboot`.
- FlexVolume host path `/usr/libexec/kubernetes` is no longer provisioned.
- Custom TLS cipher-suite settings are ignored; TLS 1.3 is the minimum for etcd and kube-apiserver.
- `-k/--kubernetes` on `containers`/`logs`/`stats`/`restart` is gone from the CLI reference; use the namespace selector instead.
- `talosctl meta write/delete` and `talosctl reset` lost `--insecure`.
- `ExtensionServiceConfig` is only supported for extension services whose manifest declares `depends: - configuration: true`.

## New-cluster / upgraded-cluster asymmetry

Two features default **on for newly generated configs** and **off for upgraded clusters**, because
the enabling document is simply absent from an existing config. This surprises people who expect an
upgrade to bring the new default.

| Feature | New clusters | Upgraded clusters | Enable with |
|---|---|---|---|
| Workload isolation (`sandboxd`) | on | off | `SecurityProfileConfig` with `workloadIsolation` |
| Filesystem trim | on (weekly) | off | `FilesystemTrimConfig` |

**Workload isolation breaks the in-tree Kubernetes `iscsi` volume plugin.** CRI containerd, kubelet
and all pods run in a dedicated PID and mount namespace, so kubelet cannot reach host `iscsid`.
Migrate to `csi-driver-iscsi` or `democratic-csi` before enabling it. All in-tree non-CSI volume
plugins are candidates for removal later.

New log source when isolation is on: `talos_logs(service="sandboxd")`.

## Quieter behaviour changes

- **NRI is no longer disabled** for CRI containerd. Opt back out with a `CRICustomizationConfig` setting `plugins."io.containerd.nri.v1.nri".disable = true`.
- **`net.ipv4.conf.{all,default}.send_redirects = 0`** by default, per CIS. Breaks a node deliberately acting as an L3 gateway that relies on ICMP redirects.
- **Flannel runs with `EnableNFTables`** — native nftables rather than the iptables-nft shim.
- **Secure Boot images drop `lockdown=confidentiality`**, effectively `lockdown=integrity`, which improves eBPF compatibility. Re-add via an Image Factory kernel cmdline if required.
- **`talosctl support` output is age-encrypted by default.** Use `--no-encryption` for the previous behaviour; see `references/troubleshooting.md`.
- **XFS allocation-group size defaults to 64 GiB** for volumes formatted by 1.14+. Existing volumes keep their geometry until wiped.
- **`noexec` dropped** for `KUBELET`, `EPHEMERAL` and `CRI`; applied to dedicated `ETCD` and `LOG` volumes when `secure: true`.
- **`OOMConfig.strictCgroupClassOrdering` defaults to `true`** — QoS class ordering is enforced when picking an OOM victim.
- **With etcd on a dedicated partition**, a reset that wipes only `EPHEMERAL` no longer clears etcd data.
- **Cluster ID base64 encoding** in generated secrets bundles changed from URL to standard encoding. Matters only for tooling that reproduces secrets.
- **Multi-node proxying is deprecated.** `-n a,b,c` still works in talosctl, but the response `Metadata` envelope is marked for removal in API v2.0. The MCP server already targets one node per call.
- **Encrypted DNS needs a correct clock.** DoT/DoH certificate validation can stall boot when the NTP servers are themselves resolved by DNS — see `references/networking/dns-and-time.md`.

## Kubernetes support

| | v1.14 | v1.13 |
|---|---|---|
| Default | 1.37.0 | 1.36.0 |
| Supported (code range) | 1.32.0 – 1.37.99 | 1.31.0 – 1.36.99 |
| Documented/tested set | 1.33 – 1.37 | 1.32 – 1.36 |
| CoreDNS | v1.14.7 | v1.14.2 |
| etcd | 3.7.1 | 3.6.11 |
| Flannel | 0.28.9 | 0.28.4 |

The documented floor (1.33) is stricter than the code floor (1.32.0). Talos will not block 1.32,
but it is outside the tested set.

## Upgrade path

Direct from **1.12 or 1.13** — `MinimumHostUpgradeVersion` is 1.12.0 and no versions are denied.
1.11 and older must hop through intermediate minors. Upstream still recommends the latest patch of
each minor as the conservative route.

Use a `talosctl` matching the target minor when running `upgrade-k8s`.
